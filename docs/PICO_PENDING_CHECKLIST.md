# PICO_PENDING_CHECKLIST — 실제 PICO 4 Ultra로만 확인할 수 있는 항목

모의 입력(`run_mock_teleop.sh`)을 통과했다고 해서 아래 항목이 확인된 것은 아닙니다. 모의 입력은 공식
televuer의 **좌표 변환 함수**만 같은 경로로 통과하고, WebXR 서버, 브라우저, 네트워크는 전혀 거치지 않습니다.

| # | 항목 | 확인 방법 | 결과 |
|---|---|---|---|
| 1 | 같은 망에서 `https://<PC_IP>:8012/?ws=wss://<PC_IP>:8012`가 열리고 인증서를 허용할 수 있음 | PICO 브라우저 | 미확인 |
| 2 | 컨트롤러 모드에서 `motion_data_ready`가 True가 되고, 축 방향(전후·좌우·상하)과 좌우 손 매핑이 맞음 | `run_pico_teleop.sh --diag`, 허브 창 | 미확인 |
| 3 | X/Y/A/B, grip, trigger(0..1 아날로그), 스틱 값과 스틱 클릭의 실제 televuer 필드명 | `--diag` 로그 | 미확인 |
| 4 | 머리 yaw 보정(`head_yaw`): 몸을 돌려도 팔 목표가 로봇 기준으로 일관됨 | 제자리에서 90° 회전 | 미확인 |
| 5 | 머리 영상(WebRTC :60001)이 헤드셋에 보이고 지연이 허용 가능함 | immersive 모드 | 미확인 |
| 6 | 트래킹 끊김(컨트롤러를 가림, Wi-Fi 끊김) 때 허브가 `INPUT LOST`로 바뀌고 손 상태를 유지함 | 의도적으로 가리기 | 미확인 (모의 dropout 시나리오는 별도로 검증 대상) |
| 7 | 컨트롤러를 가만히 들고 있어도 포즈가 0.5 s 안에 갱신됨(정지 상태를 끊김으로 오판하지 않음) | `--diag`의 `since_change_s` | 미확인 |
| 8 | 스틱 보행(`--loco-source xr`) dead zone·속도 상한이 적절함. 공식 보행 정책은 작은 명령에 발을 떼지 않으므로(시뮬 측정: 횡 0.35 m/s, 회전 0.8 rad/s에서 제자리) 스틱을 끝까지 밀어야 걷는 느낌이 괜찮은지 | 짧은 보행 | 미확인 |
| 8b | 트리거로 손을 닫을 때 확인 지연(50 ms + 새 포즈 도착)이 불편하지 않고, 실제 PICO 포즈 갱신 주기에서 전이가 누락되지 않음 | `--diag`, 빠르게 눌렀다 떼기 | 미확인 |
| 8c | 시뮬이 실시간의 약 0.3–0.4배라 팔이 손보다 늦게 따라오는 것이 조작 가능한 수준인지(속도 제한은 시뮬 시간 기준) | 집기 시도 | 미확인 |
| 8d | 헤드셋 영상: 지금은 헤드 왼눈(`front_camera`) 단안. 입체로 보려면 시뮬 이미지 서버가 오른눈(`front_right_camera`)까지 side-by-side로 보내야 함(미구현). 단안으로도 조작 가능한지 | immersive 모드 | 미확인 |
| 9 | 텔레옵 중 녹화 1회 → 검증 → preview | `record_episode.sh preview` | 미확인 |
| 10 | 장시간(10분) 텔레옵 시 프레임 드롭, 시뮬 RTF | `validate_dataset.sh` | 미확인 |

장비 없이 이미 준비한 것: 인증서(SAN에 현재 IP 포함), 접속 URL 출력, 버튼 매핑 YAML, 진단 출력, 끊김·재연결 처리 코드와
모의 시나리오(dropout/recenter), 녹화 경로. "PICO만 오면 된다"가 아니라, 위 표의 항목을 실제로 확인해야 끝납니다.
