작성 2026-11-18. 사용자 요청: "4만 모델 한번 돌려보자. sim에서. 5060은 학습중이니까 4060으로 해봐"

## 1. 구성

```
시뮬레이터 (scripts/run_act_eval.sh sim, 4060)
  ext.py PolicyBridge (G1IV_POLICY_BRIDGE=logs/run/policy_bridge.sock)
    녹화 중일 때, 녹화기가 프레임 k의 관측(step s_k 직전)을 잡을 때마다 → 카메라 4대 + arm_q + hand_q_norm 전송
    → 실행기 응답이 올 때까지 대기(lockstep) → 응답의 {"stop": outcome}이면 에피소드 종료
실행기 tools/run_act_policy.py (teleop env, 허브 대신 명령 소유자)
    관측 → 정책 서버 → action 29 → 팔: 공식 G1_29_ArmController(rt/lowcmd, 허브와 같은 속도 제한)
                                    손: rt/inspire/cmd (DFX 순서 0..1)  보행: rt/run_command/cmd [vx,vy,wz,0.8] 200 Hz 재발행
    → 15 ms 대기(DDS 전달) → 시뮬에 응답 → 시뮬이 step s_k 동안 적용 (데모 녹화와 같은 프레임 의미)
정책 서버 tools/act_policy_server.py (so101 .venv-train, LeRobot 0.6.1, 4060)
    체크포인트의 정책 + pre/post processor(정규화 통계), lerobot predict_action, 카메라 이미지는 JPEG 95로 한 번 재압축(녹화와 같음)
메시지: src/g1iv_common/framing.py (JSON + 원시 배열 바이트, pickle 없음 — Python 3.10/3.11/3.12·numpy 1/2 혼용)
```

- 정책 출력 action 29 = 팔 14(rad) + 손 12(0..1, 데이터셋 순서 L→R) + 보행 vx, vy, wz. 데이터셋은 `tools/make_act_dataset.py`.
- 녹화된 action과 허브가 보낸 명령이 같음을 확인함(손 목표 vs hand_q_sent, 팔 목표 vs arm_sent_q 차이 중앙값 0).
- 평가 에피소드 녹화는 `data/policy_eval/<날짜>/`(source=policy). `data/raw`, `data/smoke`와 섞이지 않음.
- 실행기가 끊기면(소켓 끊김, 세션 종료 등) source=policy 녹화는 즉시 `aborted`(end_reason `policy_runner_lost`)로 닫힘. 2026-11-18 22:02에는 이 처리가 없어 실행기 없이 3,387프레임(424 MB)이 녹화된 적 있음.
- 결과: `logs/policy_eval/<시각>_<label>_<mode>/summary.jsonl`(에피소드당 1줄), `ep<i>_trace.npz`(프레임별 action, 보낸 보행 명령, 들림, 몸 위치).

## 2. 사용법

